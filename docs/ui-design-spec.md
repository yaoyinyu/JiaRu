# UI设计规范 — 甲如

本文件维护长期界面约定。正式站采用米白／珊瑚的新拟态与内容平涂分层设计；当前实现与验收状态见[技术白皮书](technical-whitepaper.md)§4.8。旧玫瑰粉界面规范由现行规则替代，甲油与图片内容色继续遵循业务数据。

## 1. 设计依据与适用范围

| 场景 | 规则与实现入口 |
| --- | --- |
| 正式站页面、组件与样式 | [产品设计方案](product-ui-redesign-proposal.md)的生效设计要求、[交互改造方案](frontend-interaction-redesign-plan.md)的对应流程；实际令牌见 `src/app/globals.css` |
| 独立消费者预览 `design/consumer-v1` | [设计简报](consumer-redesign-design-brief.md)、[动效方案](consumer-redesign-motion-plan.md)及该目录样式 |
| 复用新拟态提示词 | [精简风格提示](neumorphism-hard-prompt.md)，仅摘录本规范，不另维护一套令牌 |

方案中的待实施目标与历史状态先对照白皮书及当前源码；保持正式站与独立预览各自的范围。发生规则冲突时，先满足功能、色彩保真和可访问性，再统一装饰表现；涉及产品行为调整仍按 AGENTS 同步。

## 2. 色彩、层级与排版

- 使用当前页面令牌：正式站基底 `--paper` / `--surface`，文字 `--ink` / `--muted`，强调 `--coral*`，次级底色 `--sage`，细边 `--line`。具体值以样式定义为准，避免在多个规则文件重复冻结数值。
- 交互结构使用同色系凸凹阴影，光源保持左上亮、右下暗；图片、画布、色卡和结果图采用平涂及必要的细边框。说明区以留白、字体和细边区分层级，避免所有内容都做凸起卡片。
- 主图、画布和色卡周边按产品设计方案保持至少 12px 中性间隔带，避免品牌色、渐变、毛玻璃及彩色投影干扰色彩判断。内容区按方案允许中性或纯白底；相机叠加层按对比度需求处理。
- 字体沿用项目已加载字族，建立清晰的标题、正文、辅助层级。主流程文字至少 12px，诊断等宽文字沿用明确的 11px 例外；新布局优先使用 rem 和弹性尺寸，支持浏览器文字放大与 200% 缩放。
- 正文对比度至少 4.5:1，大字至少 3:1，关键图形与焦点指示至少 3:1；状态同时提供形状、图标或文字提示。文案用少量必要文字说明动作与结果，图标按钮必须具有可访问名称。

## 3. 组件与动效

- 优先复用 `src/components/ui/` 中的按钮、弹层、上传与状态组件，修改前核对实际 API；控件提供默认、悬停、按下、焦点、禁用及适用的加载状态。
- 新拟态按钮悬停收小外阴影，按下转为内凹；输入框聚焦减浅内阴影并保留清晰焦点。普通按钮避免用位移模拟浮起；开关滑块等功能运动按其专用组件合同执行。
- 使用项目已有时长与缓动令牌，并显式列出过渡属性。避免 `transition-all`；`prefers-reduced-motion` 下关闭或减少非必要运动。
- 主要触控目标至少 44×44 CSS px；鼠标悬停之外提供等价触控和键盘入口。自定义断点按[开发与排障](agent-rules/development.md)的 Tailwind 规则实现。
- 弹层具备名称、初始焦点、焦点圈定、Escape 关闭和合理回焦；嵌套、异步关闭及触发节点消失时单独验证。删除等破坏性操作按流程提供确认或撤销。

## 4. 流程与文案

- 每页突出当前任务、主要动作和结果；导航结构、路由与状态语义以当前白皮书及实现为准。
- 长任务提供真实进度或等待说明、适用的取消入口和失败恢复；保留可恢复的输入或上一结果，重复点击与过期请求须受控。
- 表单有可见标签、错误关联和明确的提交状态；中文输入法组合期间保留正常输入与候选确认行为。
- 将辅助定位、人工复核、本地保存、云服务和启发式标签按实际能力命名。技术诊断收进按需展开区域；主流程只显示用户决策所需信息。
- 摄像头明确开启、关闭、权限失败和处理失败状态；原始相机画面与叠加 Canvas 保持坐标一致。

## 5. 验收

按变更覆盖桌面、窄屏、横竖屏、鼠标、触控、键盘、IME、缩放、软键盘、安全区和 reduced-motion。检查焦点、溢出、空态、失败、取消、恢复与资源释放；功能性横向画布按设计单独核验。报告分别登记自动化、桌面浏览器、移动真机与原生能力的验证范围和待验项；具体页面状态写白皮书与当日日志。
