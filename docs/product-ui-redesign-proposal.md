# 甲如（JiaRu）产品交互界面重设计方案

> 提出日期：2026-10-27 · 状态：**提案，未实施**
>
> 适用范围：现有 Next.js App Router 正式站（`/`、`/gallery`、`/ai-generate`、`/ar-tryon`、`/nail-analysis`、`/editor`、`/account`、`/login`、`/privacy`）。
>
> 事实基线：技术白皮书 v1.2.156 §3 功能状态总表、§4 页面与用户使用接口、§11 已知限制。本提案不改动任何路由契约、HTTP API、组件 Props、数据角色或模型门；涉及能力边界的表述一律沿用白皮书现状，不因 UI 改动而放宽或提前承诺。
>
> 与 `docs/consumer-redesign-design-brief.md` 的关系：后者是**独立本机原型**（`127.0.0.1:4318`，未注册正式路由）的消费者端设计；本提案面向**现有正式站**的交互框架重构，两者共用品牌 token 与「设计不一定是加法」原则，但落地对象不同，不互相替代。

---

## 1. 现状梳理与问题定义

基于 §3／§4 与源码，现有界面存在六类结构性问题：

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P1 | 五大能力是孤岛，链路靠 URL 参数硬拼 | `/editor?gallery=`（§4.3）、`/ai-generate?gallery=\|?collect=`（§4.4）、`/ar-tryon?gallery=\|?collect=`（§4.5）、`/editor?preset=`（§4.6）四套语义各异的参数各自实现 | 无统一「我在做什么」的对象；离开页面即丢上下文 |
| P2 | 无作品／项目持久化 | §11.3-7：编辑器笔画／成品共享与服务端持久项目协议缺失；图库「我的收录」仅浏览器 IndexedDB，跨设备同步未实现（§4.3） | 用户成果无法沉淀与复用，返回成本高 |
| P3 | 状态反馈口径分散 | 上传校验（§4.2）、摄像头 1/7 诊断步骤（§4.5）、AI 生成四态（§4.4）、fallback 琥珀声明（§4.6）、诊断面板（旧 UI 规范 §6）各按各页实现 | 同类状态呈现不一致，异常时用户无法判断下一步 |
| P4 | 长任务阻塞 | Agnes 文生图实测约 157s，图生图约 12—41s；Seedream pro 约 19.7—28.5s、lite 约 27.1—33.1s（§4.4、§3） | 用户被迫停留等待，无法并行做别的事 |
| P5 | 移动端是桌面布局的收缩版 | 现有 `Header` 为单一顶部横向导航（`src/components/Header.tsx`），五个 tab + 登录 + CTA 全部挤在一条 64px 顶栏内 | 拇指不可达、内容区被压缩 |
| P6 | 导航不体现能力边界 | 正式纹理模型 PRODUCT HOLD（§3、§11.1）、AR 待验证、无云端同步 | 用户易把「辅助定位」「AI 素材」误认为正式能力 |

**设计命题**：在不新增任何模型／服务承诺的前提下，把五个孤岛重组成一条可中断、可恢复、可沉淀的主线。

## 2. 设计目标与原则

| 原则 | 含义 | 对应的可验证行为 |
| --- | --- | --- |
| **P-1 色彩保真优先** | 试色／比色／纹理选择是产品的核心价值，任何装饰不得干扰色彩判读 | 主图与色卡周边禁渐变、毛玻璃、彩色阴影；背景为中性或纯白（§6.3） |
| **P-2 一方案到底** | 全站只有一个主线对象「方案」，所有页面围绕它读写 | 任意页面可见当前方案与进度；跨页不需重新选择来源 |
| **P-3 可中断可恢复** | 任何超过 15s 的任务都必须给出「离开去做别的」的出口 | 长任务任务化；草稿本地暂存并可恢复 |
| **P-4 状态即契约** | 12 类状态有统一呈现与出口，不各页自定义 | 状态组件库覆盖全部 12 类（§9.1） |
| **P-5 操作在下、内容在上** | 移动端主操作常驻拇指区，预览占上半屏 | 底部工具坞承载主 CTA，画布区域不被操作条遮挡 |
| **P-6 边界诚实** | 辅助定位、AI 素材、未验收能力必须常显且不可关闭 | 沿用 §4.6 琥珀声明语义，统一为单一声明组件 |

反原则（明确不做）：不新增上传通道、不引入新的第三方依赖、不用动效掩盖等待、不因 UI 改动放宽任何质量门。

## 3. 核心概念：方案对象与主线

### 3.1 统一主线

```text
选款（灵感／AI／自定义） → 试（AR 试戴 或 图片试色） → 改（精修／换色／校准） → 存（方案库） → 分享（给美甲师）
```

主线对象 **方案（Plan）**：

```ts
interface LookPlan {
  id: string;                 // 本地 UUID；云同步后由服务端下发权威 id
  name: string;               // 款式名
  source: {                   // 来源：决定标识与授权提示
    kind: "gallery" | "ai" | "collect" | "custom";
    refId?: string;           // gallery id / collect id
    engine?: "agnes" | "seedream-pro" | "seedream-lite";
    isAiMaterial: boolean;    // AI 素材常显标识
  };
  nail: { shape?: string; length?: string };
  palette: string[];          // 色板（≤5，对应拇指—小指）
  textures?: string[];        // 五指纹理引用（本地 blob 键）
  stage: "draft" | "generated" | "tried" | "saved";
  scope: "device" | "cloud";  // 存储范围，UI 必须明示
  updatedAt: number;
}
```

首期存储沿用既有浏览器 IndexedDB（与 §4.3 `jiaru-gallery` 同库不同 store），`scope` 恒为 `"device"`，UI 明示「仅保存在这台设备」；云同步属 §11.3-2 未实现能力，UI 不得预留可点击的假入口。

### 3.2 路由参数统一与兼容

| 现状 | 提案 | 兼容要求 |
| --- | --- | --- |
| `/editor?gallery=<id>` | `/editor?look=<id>&from=gallery` | 旧参数继续解析，映射为等价 `look`，**不得移除**（§4.3 契约） |
| `/editor?preset=<色名>` | `/editor?look=<id>&from=analysis` | 同上（§4.6 契约） |
| `/ai-generate?gallery=\|?collect=` | `/ai-generate?look=<id>&from=gallery` | 同上（§4.4 契约） |
| `/ar-tryon?gallery=\|?collect=` | `/ar-tryon?look=<id>&from=gallery` | 同上（§4.5 契约） |

兼容层为纯前端映射，不改变任何 API；现有测试与文档中的旧 URL 行为必须保持一致。

## 4. 信息架构与页面清单

### 4.1 全局结构（三层）

```text
L1 全局导航   桌面：左侧 240px 固定 rail   移动：底部 4 项 tab bar
L2 页面步骤   创作／个性化等多步流程用步进条（可返回、可跳过，保留已填项）
L3 上下文     面包屑 + 「返回 <来源页>」，返回必须回到来源路由与滚动位置
```

### 4.2 页面清单

| 页面（路由不变） | 新角色 | 主要变化 |
| --- | --- | --- |
| `/` 首页 | 今日灵感 + 三个动作入口 + 主线恢复 | 顶部新增「继续上次的方案」恢复条；三个入口为「看图找款／AI 创作／直接试戴」 |
| `/gallery` 灵感 | 选款起点 | 桌面双栏（筛选托盘 + 瀑布网格）／移动单列 + 底部筛选抽屉；卡片三入口收为「试色／AI 相似款／AR 试戴」并统一写入当前方案 |
| `/ai-generate` 创作 | 生成起点 | 桌面「左控制台／右预览」；移动「参数 → 结果」两步；生成提交后任务化（§5.3） |
| `/ar-tryon` 试戴 | 实时验证 | 摄像头／照片双模式卡改为独立入口卡；五指独立校准收进底部抽屉；朝向指示与诊断统一 |
| `/nail-analysis` 个性化 | 推荐与决策 | 四步向导（上传 → 问卷 → 分析 → 推荐），推荐卡可就地建立方案 |
| `/editor` 精修 | 精细调整 | 画布上方、工具坞下方；「应用到全部」+ 单指覆盖；重置／撤销语义沿用 v1.1.658 修复后的口径 |
| `/account` 我的 | 沉淀与治理 | 账号／偏好／我的方案／隐私开关分区；账号与设备偏好不一致时显式提示（§10 已知缺口） |
| `/looks`（新增，P3） | 方案库 | 列表（草稿／已生成／已试戴／已保存）+ 方案卡详情；首期仅本地 |
| `/login`、`/privacy` | 不变 | 仅套用统一壳层与状态组件 |

新增页面只有 `/looks`，且首期为纯本地实现；不新增任何服务端接口。

## 5. 核心操作流程

### 5.1 流程 A：灵感款 → AR 试戴（最高频）

```text
1 /gallery 卡片「AR 试戴」
2 自动建立／更新当前方案（来源=gallery）→ 跳 /ar-tryon?look=<id>&from=gallery
3 自动取图 → 打开多指选取器（沿用 §4.5 既有自动带入链路）
4 用户点「开启摄像头」（页面内唯一按钮，沿用 §4.5 修复后口径）
```

现状为 5 次主操作 + 5 次手指分配；目标为 **2 次主操作进入摄像头授权**，手指分配由自动带入承担。

### 5.2 流程 B：灵感款 → 图片试色 → 保存

```text
/gallery「试色」 → /editor?look=<id> → 上传手部图（校验：JPG/PNG/WebP、≤10MB、320–4096px，§4.2）
→ 灵感色预涂（§4.3 既有启发式，UI 明示为启发式不等同真实甲油色）
→ 逐指微调 → 原分辨率导出（v1.1.658，4096 方图导出 4096 方图）
```

### 5.3 流程 C：AI 创作（长任务）

```text
选引擎 → 比例/尺寸 → 提示词 → 提交
  ├─ ≤15s：就地等待，显示已耗时与「后台继续」出口
  └─ >15s：转为后台任务，结果写入方案库；用户可离开
```

**实现前提**：真正的后台任务需要服务端任务队列与结果持久化（§11.3-5 未完成）。**首期降级方案**：保持页面不跳转，但结果面板可最小化、明确显示已耗时、提供「取消」；任务化随 §11.3-5 落地后再启用。UI 不得在队列存在前宣称「关闭页面也能继续生成」。

### 5.4 流程 D：个性化分析 → 决策

```text
上传手背图 → 场景问卷 → 本地分析 → 推荐卡（甲型/长度/色系/理由/置信度/命中规则，§4.6）
→ 「用这个色试戴」建立方案并跳 /editor?look=<id>&from=analysis
```

0 候选时不产出任何推荐（§4.6），空态必须给出可行动作（重拍／改用手动选色），不能只显示文案。

## 6. 视觉风格体系

### 6.1 品牌与继承

沿用 `docs/consumer-redesign-design-brief.md` §8.1 已确认的品牌 token，作为全站唯一色值来源：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--paper` / `--surface` | `#f7f4ee` | 基底与交互面 |
| `--ink` | `#292a27` | 标题、正文、主按钮 |
| `--coral` / `--coral-text` / `--coral-deep` / `--coral-soft` | `#ac5145` / `#a34b3f` / `#884338` / `#f0e2db` | 强调与选中态 |
| `--sage` | `#e3e7dd` | 次级内容底色 |
| `--shadow-light` / `--shadow-dark` | `#fffdf8` / `#d3ccbd` | 双光源（左上亮／右下暗） |
| `--muted` | `#67685f` | 说明文字（`#f7f4ee` 上 5.14:1） |

旧 `docs/ui-design-spec.md` 的玫瑰粉（`#e8a0bf`）体系**不并入**正式站的交互层，避免与新拟态光源语言冲突；仅在需要历史一致性时作为参考。

### 6.2 分层混合风格（本方案相对现有原型的关键调整）

新拟态软 UI 依赖双光源阴影，在**图片密集与色彩判读场景**会引入邻域明暗干扰。因此采用分层：

| 层 | 元素 | 风格 |
| --- | --- | --- |
| 结构层 | 导航 rail／tab bar／卡片／面板／按钮／chip／输入框 | 新拟态：凸起＝可交互，凹陷＝已选／输入／托盘；悬停＝阴影缩小无位移；按压＝凸起转凹陷 |
| 内容层 | 手部主图／画布／纹理预览／结果图 | **平涂 + 1px 中性描边 + 无环境阴影**，禁止渐变、毛玻璃、彩色投影 |
| 状态层 | 声明条／toast／错误区 | 声明条用珊瑚 soft 底 + 深珊瑚字；toast 用墨底 + 柔和环境投影 |

### 6.3 色彩保真硬规则（可断言）

1. 主图／画布／色卡周边 **12px** 内不得出现品牌色、渐变、`backdrop-filter`、彩色阴影；
2. 「取色／试色／比色」三类视图的背景必须为纯白或中性灰，**禁用** `backdrop-filter` 与渐变；
3. 同一甲面色块在编辑视图与浏览视图的取样区（中心 9×9 像素均值）差异 **ΔE\*ab ≤ 2**（脚本断言）；
4. 深色模式为可选项；若启用，色彩判读区仍须渲染为中性灰卡片，不得在深色背景上直接比色。

### 6.4 字体与图标

- 标题：本地衬线子集（沿用 §4.7 已落地的 OFL 许可 Noto Serif SC 衍生子集，`font-display: swap`）；新增标题须检查字形覆盖；
- 正文／用户输入：系统字体，中文 16px 起；
- 图标：全站内联 SVG 矢量，**禁用 emoji**（延续 v1.1.488 口径）；
- 文案：全站中文；术语统一见表 6.5。

### 6.5 术语对照（UI 文案强制）

| 术语 | 含义 | 禁用表述 |
| --- | --- | --- |
| 款式 Look | 图库／AI 生成的完整设计 | 模板、素材（易混淆授权） |
| 方案 Plan | 款式 + 甲型长度 + 色板 + 备注 | 作品（暗示已发布） |
| 试色 | 图片编辑上色 | 试戴 |
| 试戴 | AR 实时叠加 | 试色 |
| 纹理 / 纯色 | AR 两种模式（§4.5） | 图案（与纹理混用） |
| 收录 | 浏览器本地 IndexedDB 收藏（§4.3） | 收藏夹（暗示云同步） |
| 辅助定位 | fallback 无像素级 mask 路径 | 自动识别、AI 识别成功 |
| AI 素材 | Seedream／Agnes 生成图 | 真实买家秀、实拍 |

## 7. 布局结构与栅格

### 7.1 断点与容器

| 断点 | 宽度 | 容器 | 栅格 |
| --- | --- | --- | --- |
| XS | <480 | 全宽 - 16px 边距 | 4 列 |
| SM | 480–767 | 全宽 - 20px | 4 列 |
| MD | 768–1023 | 720px 居中 | 8 列 |
| LG | 1024–1439 | 240px rail + 1160px 内容 | 12 列 |
| XL | ≥1440 | 240px rail + 1200px 内容 | 12 列 |

### 7.2 桌面（≥1024px）

```text
┌──────────┬──────────────────────────────────────────┐
│ 品牌标识  │  任务条：当前方案 · 亮片闪粉 · 已试戴      │
│ 为你      ├──────────────────────────────────────────┤
│ 试戴      │                                          │
│ 创作      │   内容区（受控最大宽度 1200px）            │
│ 我的      │   控制台 / 预览 双栏（创作类页面）          │
│ ───────── │                                          │
│ 灵感      │                                          │
│ 个性化    │                                          │
└──────────┴──────────────────────────────────────────┘
```

- 左 rail 固定 240px、不随内容滚动；当前项＝凹陷 + 珊瑚 soft 底 + 珊瑚指示条；
- 创作类页面左栏控制台 ≤400px，右栏预览自适应；
- 悬停仅作补充反馈，**不承担唯一操作入口**（§2.1 既有边界）。

### 7.3 移动（<768px）

```text
┌────────────────────────┐
│ 精简页头（≤56px）       │  ← 返回 + 标题 + 一个次级动作
├────────────────────────┤
│                        │
│   预览 / 画布（上方）    │  ← 占剩余高度，不被遮挡
│                        │
├────────────────────────┤
│   工具坞（拇指区）       │  ← 主 CTA + 当前步骤操作
├────────────────────────┤
│  为你  试戴  创作  我的  │  ← 底部 tab bar，安全区上移
└────────────────────────┘
```

- 主 CTA 常驻工具坞；画布上方；两者不重叠；
- 软键盘弹出时收起底部 tab bar（沿用 §4.7 已验证的 VisualViewport 方案）；中文合成输入不重建输入节点。

## 8. 导航方式

### 8.1 三层导航与任务条

| 层 | 桌面 | 移动 |
| --- | --- | --- |
| L1 全局 | 左侧 rail（6 项：为你／试戴／创作／我的 + 灵感／个性化） | 底部 4 项 tab bar（为你／试戴／创作／我的），灵感与个性化从「为你」进入 |
| L2 步骤 | 顶部步进条（创作、个性化） | 底部工具坞内嵌「第 2 / 4 步」+ 进度条 |
| L3 上下文 | 面包屑「灵感 › 亮片闪粉 › 试戴」 | 页头返回箭头 + 来源名 |

**任务条（Mission Bar）**：桌面位于内容区顶部、移动位于页头下方。常显当前方案缩略图、名称、阶段标签（草稿／已生成／已试戴／已保存）、进度（如「已试戴 3/5 指」），右侧「查看方案」。点击展开方案详情抽屉（来源、引擎、色板、备注、存储范围）。

### 8.2 导航行为契约

1. 跨页返回必须回到**来源路由与滚动位置**；
2. 弹层关闭后焦点返回触发元素；跨页返回聚焦主体，不聚焦新页同名按钮；
3. 快速重开弹层不被旧 `close` 事件解锁（沿用 §4.7 已验证行为）；
4. 就地更新：收藏、关注、标签切换、灵感词、换款、上传、生成开始**只更新对应控件／区块**，不重建页面、不重设滚动、不发起多余请求（沿用 §8.10／§8.11 口径）；
5. 仅路由切换、登录态切换、诊断场景保留整页渲染。

## 9. 关键交互反馈

### 9.1 统一状态机（12 类）

组件库提供 `<TaskState>`，全站唯一入口；各页不得自定义同类状态。

| 状态 | 典型触发 | 呈现 | 出口 |
| --- | --- | --- | --- |
| `idle` | 初始 | 空态卡 + 主 CTA + 一句话能力说明 | 开始 |
| `validating` | 上传本地校验（§4.2） | 按钮转「检查中」+ 禁用重复提交 | 通过进 `loading`；失败进 `error-input` |
| `loading-determinate` | 摄像头启动 1/7 步骤（§4.5）、模型加载 | 进度条 + 当前步骤文案 + 取消 | 完成／取消 |
| `loading-indeterminate` | AI 生图、纹理推理 | 骨架屏（与真实内容同格等量，高度差 ≤1px）+ 已耗时；>2s 显示预计区间；>15s 显示「后台继续」/「取消」 | 完成／取消／转后台 |
| `success` | 生成成功、保存成功 | 就地更新 + 轻档粒子爆散（9 粒）+ 文案；不整页重绘 | 下一步 |
| `empty` | 0 候选（§4.6）、无收藏、无搜索结果 | 图示 + 原因 + **可行动作**（重拍／换词／手动添加） | 重试／换输入 |
| `error-input` | MIME 不符、>10MB、分辨率越界、提示词 0 或超长 | 内联错误（贴近出错控件）+ 保留已填内容 | 修正后重试 |
| `error-recoverable` | 网络超时、跨域 fetch 失败（§4.3 收录降级）、429/503 | 错误卡 + 「重试」+ 降级提示 | 重试／降级方案 |
| `error-fatal` | 摄像头权限拒绝、无设备、WebGPU 与 WASM 均不可用、MediaPipe 资源 404 | 分步排查指引（沿用 §4.5 七步排查顺序） | 按指引操作／换入口 |
| `degraded` | fallback 辅助定位、正式模型未部署 | **常显不可关闭**的琥珀声明条 + 结果照常展示 | 继续（须人工确认） |
| `offline` | 断网 | 顶部细条提示 + 本地可用能力仍可用；需网络入口置灰并说明 | 恢复后自动重试 |
| `canceled` | 用户取消、离开页面 | 恢复触发前状态 + 保留草稿 | 重新开始／恢复草稿 |

### 9.2 动效规范

沿用 `docs/consumer-redesign-motion-plan.md` 已落地口径，不新增动效种类：

| 动效 | 规格 |
| --- | --- |
| 按压 | `.is-pressed` 140ms `scale(.96)` → 释放 340ms `cubic-bezier(.34,1.56,.64,1)` 过冲落位；**平移分量恒为 0** |
| 悬停（仅细指针） | 阴影缩小，无位移 |
| 成功 | 轻档 9 粒粒子爆散；失败不爆散 |
| 页面／路由 | 短淡入上移（页面 0.65s、元素 0.45s）；快速切页取消旧动画 |
| 骨架 → 内容 | 同格等量替换，高度差 ≤1px |
| `prefers-reduced-motion` | 关闭脚本水波／爆散／回弹，弹层与勾选瞬时到位 |

禁止：为展示动效增加必经步骤；用动画掩盖等待；在画布区叠加任何位移。

### 9.3 表单与输入

- 输入校验在**失焦 + 提交**双触发，错误内联、不弹窗打断；
- 计数器实时（提示词上限 Agnes 520 / Seedream 300，随引擎切换，§4.4）；
- 中文合成输入期间不触发校验与格式化；
- 所有输入保留草稿，切页不丢（沿用 §4.7 草稿隔离口径）。

## 10. 效率与易用性提升

### 10.1 步数对照（目标值，待实测，非已达成）

| 编号 | 任务 | 现状主要操作次数 | 目标次数 | 提升机制 |
| --- | --- | --- | --- | --- |
| T1 | 灵感款 → AR 试戴 | 5 次主操作 + 5 次手指分配 | 2 次主操作 | 方案对象跨页携带来源与纹理，自动带入选取器 |
| T2 | 灵感款 → 图片试色 | 5+（含重新选色） | 3 | 灵感色预涂 + 方案携带色板 |
| T3 | AI 创作等待 | 阻塞 9—157s | 阻塞 ≤15s 可见出口 | 长任务提示 +（P3）任务化 |
| T4 | 五指同色 | 10（逐指切 tab + 选色） | 1—6 | 「应用到全部」+ 单指覆盖 |
| T5 | 分析 → 试色 | 5（含跳转与重选） | 4 | 推荐卡就地建立方案 |
| T6 | 中断后继续 | 不可用（无草稿） | 1 | 首页「继续上次的方案」恢复条 |

### 10.2 机制说明

1. **上下文继承**：跨页统一携带 `look`，消除重复选款；
2. **就地更新**：收藏、标签、换款等交互不重绘页面，避免滚动与焦点丢失；
3. **批量 + 覆盖**：五指配色从「逐指操作」改为「默认全选 + 例外覆盖」；
4. **可中断**：长任务给出明确出口，草稿随时可恢复；
5. **状态一致**：12 类状态全站一致呈现，用户学习一次即可迁移；
6. **边界前置**：能力声明与限制在入口处常显，避免用户在流程末端才发现不匹配。

## 15. 风险、边界与禁止项

1. 正式纹理模型 PRODUCT HOLD（§3、§11.1）：任何界面不得把 fallback 辅助定位表述为「自动识别成功」，不计入正式识别成功率或 Beta 直接可用率；
2. AR 摄像头需 HTTPS 或 `localhost`，`/ar-demo` 外网必然不可用（§11.4）：UI 不得隐藏该前提；
3. 跨设备同步未实现（§11.3-2）：方案库必须明示「仅本机」，不得出现不可用却可点的同步入口；
4. 隐私文案待修订（§10）：改造后仍须与账户、Seedream 与主动生图数据流一致，不得沿用「无账户体系」表述；
5. 不因 UI 改动放宽任何质量门：源图筛选、完整 mask 审核、来源隔离、真机与 Beta 门保持现状；
6. 不新增上传通道与第三方依赖；不改变本地优先的数据边界；
7. 不删除或弱化任何现有的能力边界声明。

## 16. 评审与迭代机制

1. 每轮评审记录：版本号、评审日期、样本与口径、通过项、未通过项、未决项；
2. 未通过项进入下一轮并保留原失败记录，**不覆盖、不删除、不把旧失败重算为通过**；
3. 度量口径（步数定义、受试者条件、设备与浏览器版本、网络条件）一旦冻结，轮次间不得变更；确需变更须另立版本并保留旧值；
4. 任何「通过」结论必须绑定可重放的机器记录或截图存证；模拟结果须标注为模拟；
5. 路线变更（如 P4 是否实施）须在当日 dev-log 记录旧值、新值、原因与证据。
