### 1.1 剩余问题定义（修订版）

基于白皮书§3/§4 与源码、截图核对，现有界面剩余六类结构性问题：

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P1 | 五大能力是孤岛，链路靠 URL 参数硬拼 | `/editor?gallery=\|?preset=`、`/ai-generate?gallery=\|?collect=`、`/ar-tryon?gallery=\|?collect=` 四套语义各异的参数各自实现（v1.2.161 源码实测） | 无统一「我在做什么」的对象；离开页面即丢上下文 |
| P2 | 无作品／项目持久化 | 白皮书§11.3-7：编辑器笔画／成品共享与服务端持久项目协议缺失；图库「我的收录」仅浏览器 IndexedDB，跨设备同步未实现（白皮书§4.3） | 用户成果无法沉淀与复用，返回成本高 |
| P3 | 状态反馈口径分散 | 上传校验（白皮书§4.2）、摄像头 1/7 诊断步骤（白皮书§4.5）、AI 生成四态（白皮书§4.4）、fallback 琥珀声明（白皮书§4.6）各按各页实现 | 同类状态呈现不一致，异常时用户无法判断下一步 |
| P4 | 长任务阻塞 | Agnes 2.5 Flash 实测文生图约 9.1s、图生图约 102.3s；Seedream pro 约 19.7—28.5s、lite 约 27.1—33.1s（白皮书§3 v1.2.147 口径）【修订：初版 157s/12—41s 为 2.1 Flash 旧数据】 | 用户被迫停留等待，无法并行做别的事 |
| P5 | 导航不承载主线上下文 | 导航结构已统一（v1.2.160），但跨页后「我在用哪个款式、进行到哪步」无载体；首页无恢复条 | 【修订：替代初版 P5「64px 旧顶栏」——该布局已被 v1.2.158—160 替换，现桌面页头实测约 88px】跨页上下文丢失 |
| P6 | 能力边界不随流程承载 | 首页能力边界卡为静态说明（已实装）；进入流程后 AI 素材标记、辅助定位声明散在各页，无方案级常显位 | 用户易把「辅助定位」「AI 素材」误认为正式能力 |

**设计命题**：在不新增任何模型／服务承诺的前提下，把五个孤岛重组成一条可中断、可恢复、可沉淀的主线。

## 2. 设计目标与原则

| 原则 | 含义 | 对应的可验证行为 |
| --- | --- | --- |
| **P-1 色彩保真优先** | 试色／比色／纹理选择是产品的核心价值，任何装饰不得干扰色彩判读 | 主图与色卡周边禁渐变、毛玻璃、彩色阴影；背景为中性或纯白（§6.3） |
| **P-2 一方案到底** | 全站只有一个主线对象「方案」，所有页面围绕它读写 | 任意页面可见当前方案与进度；跨页不需重新选择来源 |
| **P-3 可中断可恢复** | 任何超过 15s 的任务都必须给出「离开去做别的」的出口 | 长任务任务化（P5 后）；草稿本地暂存并可恢复 |
| **P-4 状态即契约** | 12 类状态有统一呈现与出口，不各页自定义 | 状态组件库覆盖全部 12 类（§9.1） |
| **P-5 操作在下、内容在上** | 移动端主操作常驻拇指区，预览占上半屏 | 底部工具坞承载主 CTA，画布区域不被操作条遮挡 |
| **P-6 边界诚实** | 辅助定位、AI 素材、未验收能力必须常显且不可关闭 | 沿用白皮书§4.6 琥珀声明语义，统一为单一声明组件 |

反原则（明确不做）：不新增上传通道、不引入新的第三方依赖、不用动效掩盖等待、不因 UI 改动放宽任何质量门。

### 2.1 平台优先级与既有边界【新增】

**优先级：桌面端（网页）第一，移动端第二。** 依据：

1. 受控环境全量（L4′）决策下，当前可验收环境为桌面 Chrome/Edge 与本机服务；真机摄像头受 HTTPS 前置约束（白皮书§4.1，`getUserMedia` 需安全上下文），AR 真机验收天然后置；
2. 桌面路径已有完整工程验证与截图基线（白皮书§4.8 v1.2.159/160 验收）；
3. HIG 的交互原则（反馈、层级、诚实边界、无障碍）跨平台一致，桌面先行不产生规范分叉。

执行含义：§14 分期按「桌面优先实施与验收」排序；**桌面优先只决定顺序，不降低 §12/§13 的移动端验收线**；移动端条目继续保留并在到达时以真机证据闭合（L4 未决项不动）。

**既有边界（沿用简报§8 已验证口径）**：悬停仅作补充反馈，不承担唯一操作入口；所有操作必须有可点击/可聚焦的等价路径。

## 3. 核心概念：方案对象与主线

### 3.1 统一主线

```text
选款（灵感／AI／自定义） → 试（AR 试戴 或 图片试色） → 改（精修／换色／校准） → 存（方案库） → 分享（给美甲师）
```

主线对象 **方案（Plan）**：

```ts
interface LookPlan {
  id: string;                 // 本地 UUID；云同步后由服务端下发权威 id
  name: string;               // 款式名
  source: {                   // 来源：决定标识与授权提示
    kind: "gallery" | "ai" | "collect" | "custom";
    refId?: string;           // gallery id / collect id
    engine?: "agnes" | "seedream-pro" | "seedream-lite";
    isAiMaterial: boolean;    // AI 素材常显标识（P6 承载位）
  };
  nail: { shape?: string; length?: string };
  palette: string[];          // 色板（≤5，对应拇指—小指）
  textures?: string[];        // 五指纹理引用（本地 blob 键）
  stage: "draft" | "generated" | "tried" | "saved";
  scope: "device" | "cloud";  // 存储范围，UI 必须明示
  updatedAt: number;
}
```

首期存储沿用既有浏览器 IndexedDB（与白皮书§4.3 `jiaru-gallery` 同库不同 store；DB 名与 store 已实测：`jiaru-gallery` / `collects`），`scope` 恒为 `"device"`，UI 明示「仅保存在这台设备」；云同步属白皮书§11.3-2 未实现能力，UI 不得预留可点击的假入口。

### 3.2 路由参数统一与兼容【待实施】

| 现状（v1.2.161 源码实测仍消费） | 提案 | 兼容要求 |
| --- | --- | --- |
| `/editor?gallery=<id>` | `/editor?look=<id>&from=gallery` | 旧参数继续解析，映射为等价 `look`，**不得移除**（白皮书§4.3 契约） |
| `/editor?preset=<色名>` | `/editor?look=<id>&from=analysis` | 同上（白皮书§4.6 契约；现行为：与 `?gallery=` 同传时 gallery 优先） |
| `/ai-generate?gallery=\|?collect=` | `/ai-generate?look=<id>&from=gallery` | 同上（白皮书§4.4 契约） |
| `/ar-tryon?gallery=\|?collect=` | `/ar-tryon?look=<id>&from=gallery` | 同上（白皮书§4.5 契约） |

兼容层为纯前端映射，不改变任何 API；现有测试与文档中的旧 URL 行为必须保持一致。

### 3.3 方案解析与悬空降级【新增】

`?look=<id>` 的解析顺序与降级（外链、新标签页、清空存储、分享给他人的统一处理）：

1. **命中**：从 IndexedDB 读到方案记录 → 恢复方案、来源标记与阶段；
2. **refId 可重建**：方案缺失但 `source.refId` 仍可解析（图库素材/收录仍在）→ 以 refId 重建等价方案（`stage="draft"`，UI 标注「方案已按原款式重建」）；
3. **完全悬空**：refId 也无法解析（素材变更、收录已删）→ **可行动空态**：「原方案不存在或已在本机清除」+ 动作（去图库重选 / 开始空白方案 / 返回来源页）。

禁止行为：静默当作无来源继续；引用不存在的能力（如「从云端恢复」）；空态只给文案不给动作。空态使用 §9.1 `empty` 状态组件呈现。

## 5. 核心操作流程

### 5.1 流程 A：灵感款 → AR 试戴（最高频）

```text
1 /gallery 卡片「AR 试戴」
2 自动建立／更新当前方案（来源=gallery）→ 跳 /ar-tryon?look=<id>&from=gallery
3 自动取图 → 打开多指选取器（沿用白皮书§4.5 既有自动带入链路，v1.1.583 口径）
4 用户点「开启摄像头」（页面内唯一按钮，该次点击直接触发权限请求，白皮书§4.5）
```

现状为 5 次主操作 + 5 次手指分配；目标为 **2 次主操作进入摄像头授权**，手指分配由自动带入承担（目标值，待实测）。

### 5.2 流程 B：灵感款 → 图片试色 → 保存

```text
/gallery「试色」 → /editor?look=<id> → 上传手部图（校验：JPG/PNG/WebP、≤10MB、320–4096px，白皮书§4.2）
→ 灵感色预涂（白皮书§4.3 既有启发式，UI 明示为启发式不等同真实甲油色）
→ 逐指微调 → 原分辨率导出（v1.1.658 口径：4096 方图导出 4096 方图）
```

### 5.3 流程 C：AI 创作（长任务）【修订：首期语义】

```text
选引擎 → 比例/尺寸 → 提示词 → 提交
  ├─ 全程：就地等待，显示已耗时与「取消」（取消语义见 §9.4）
  └─ 首期（P5 前）：结果面板可最小化，页面不得关闭宣称后台继续
（P5 后台任务化后：>15s 可转后台，结果写入方案库，用户可离开——依赖白皮书§11.3-5）
```

**实现前提**：真正的后台任务需要服务端任务队列与结果持久化（白皮书§11.3-5 未完成）。UI 不得在队列存在前宣称「关闭页面也能继续生成」。实测时长口径（白皮书§3 v1.2.147）：Agnes 2.5 Flash 文生图约 9.1s、图生图约 102.3s；Seedream pro 约 19.7—28.5s、lite 约 27.1—33.1s。

### 5.4 流程 D：个性化分析 → 决策

```text
上传手背图 → 场景问卷 → 本地分析 → 推荐卡（甲型/长度/色系/理由/置信度/命中规则，白皮书§4.6）
```

0 候选时不产出任何推荐（白皮书§4.6），空态必须给出可行动作（重拍／改用手动选色），不能只显示文案。

## 9. 关键交互反馈

### 9.1 统一状态机（12 类）【待实施】

组件库提供 `<TaskState>`，全站唯一入口；各页不得自定义同类状态。

| 状态 | 典型触发 | 呈现 | 出口 |
| --- | --- | --- | --- |
| `idle` | 初始 | 空态卡 + 主 CTA + 一句话能力说明 | 开始 |
| `validating` | 上传本地校验（白皮书§4.2） | 按钮转「检查中」+ 禁用重复提交 | 通过进 `loading`；失败进 `error-input` |

### 9.4 破坏性操作与取消【新增】

依据 HIG：破坏性操作必须醒目标识，且确认或可撤销；不得让破坏性按钮与安全按钮同位同色。

1. **删除方案 / 清空方案库**（§14 P4 随 `/looks` 落地）：二次确认对话框，明示名称与数量、后果「不可恢复（仅存本机，无回收站）」；确认按钮用 `--coral-deep` 警示色并与取消按钮物理分离；仅当会话内可实际回滚时提供「撤销」，否则不提供假撤销；
2. **取消 AI 生成**：立即停止等待、恢复可输入态、保留草稿与参数；服务端请求按现状继续至返回后丢弃结果（首期无服务端取消通道，白皮书§5 契约不变），UI 如实提示「已取消等待，本次结果不会保存」，不得假装请求已终止；
3. **覆盖保存同名方案**：确认对话框列出将覆盖的旧方案名称与时间；
4. **离开有未保存草稿的页面**：路由内拦截提示（`beforeunload` 或应用层确认），明确「仅保存在这台设备」。

## 15. 风险、边界与禁止项

1. 正式纹理模型 PRODUCT HOLD（白皮书§3、§11.1）：任何界面不得把 fallback 辅助定位表述为「自动识别成功」，不计入正式识别成功率或 Beta 直接可用率；
2. AR 摄像头需 HTTPS 或 `localhost`，`/ar-demo` 外网必然不可用（白皮书§11.4）：UI 不得隐藏该前提；
3. 跨设备同步未实现（白皮书§11.3-2）：方案库必须明示「仅本机」，不得出现不可用却可点的同步入口；
4. 隐私文案待修订（白皮书§10）：改造后仍须与账户、Seedream 与主动生图数据流一致，不得沿用「无账户体系」表述；
5. 不因 UI 改动放宽任何质量门：源图筛选、完整 mask 审核、来源隔离、真机与 Beta 门保持现状；
6. 不新增上传通道与第三方依赖；不改变本地优先的数据边界；
7. 不删除或弱化任何现有的能力边界声明；
8. 【新增】桌面优先只决定实施与验收顺序，不降低 §12/§13 移动端验收线；L4 真机未决门保持；
9. 【新增】对【生效】条目的任何改动（含导航结构与令牌）都是对已实装设计系统的实质变更，须按白皮书§1.3 同步版本，不得以「设计微调」名义绕过。
