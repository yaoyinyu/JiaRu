# 美甲纹理提取恢复方案（2026-07-31）

> 文档版本：v1.2（第二现场图修订方案，已完成实施前复审）
> 状态：v1.0方案已完成实施与验收；v1.2低对比裸色甲面补充方案批准实施
> 适用入口：`/ar-tryon` → “纹理” → “多纹理提取”

## 1. 问题定义与成功标准

用户提供的现场图包含五枚完整、清晰、已上色甲面，但界面最终进入人工添加模式，区域数为0。当前正式ONNX文件不存在，不能部署已被发布质量门拒绝的candidate5，也不能通过降低正式模型阈值绕过发布治理。因此，本方案只修复已获准存在的浏览器本地辅助定位链路，不改变生产模型、共享阈值或产品HOLD状态。

本次修复必须同时满足：

1. 当前现场图的临时原图裁片自动返回5个真实甲面候选，0个背景/皮肤/衣物候选；
2. 五个候选均分配到唯一手指，允许一次点击完成五纹理提取；
3. 低饱和银色、黑色、镜面高光和星形装饰不再因固定灰度/饱和度门漏检；
4. 已有“衣物、远端背景、单个歧义物体必须拒绝”的安全回归继续通过；
5. 模型不可用、手部关键点不可用时仍保留可读诊断，不把辅助定位表述为正式模型PASS；
6. 不运行candidate5推理、训练、导出、登记、部署或freeze。

## 2. 当前机器证据

- Git基线：`master`，HEAD `3e4561c80abe79b21c317168f652a5088df540ee`，单worktree，工作区和暂存区干净。
- `public/models/nail-texture-seg/manifest.json`声明`nail-texture-seg-v1.onnx`，但该文件在磁盘不存在；WebGPU与WASM初始化均失败属于当前已知阻塞，不是本次通过辅助算法可以伪装消除的错误。
- 现场截图裁出的903×1195参考图区在真实页面复现为局部近景3/5，而不是稳定5/5；保留的中心约为拇指、中指、小指，食指与无名指漏检，控制台0 error。
- 导出诊断记录`backend=fallback`，模型失败后进入局部近景路径；正式saliency候选仍仅供诊断，没有进入用户可确认区域。
- `createNailCandidatesFromHandGeometry()`在高置信`palm`时整手返回0；它说明完整手部路径不能覆盖本图，但本次证据没有证明需要立刻放宽这条安全门。未经像素复核的掌面指骨椭圆仍可能落到指腹，因此本次不以取消该门作为修复手段。
- 对现场临时裁片按当前局部检测器逐组件复算后，五枚甲面都形成了独立连通组件；食指和无名指的面积、长宽、填充率、灰度方差和触边检查均通过，仅被`directSmoothSkinRatio < 0.24`拒绝。当前缺失不是组件桥接，也不是固定灰度门直接漏掉。
- 当前`directSmoothSkinRatio`同时要求颜色属于皮肤且局部拉普拉斯均值小于20。现场图的干燥皮肤、甲缘和镜面高光提高了局部边缘响应，导致食指/无名指周围虽然原始肤色环充分，仍被“平滑”条件误判。机器复算中关键甲面周围原始肤色环接近完整，而平滑肤色环显著下降，证明单一平滑度硬门是当前直接根因。
- 同图确有一个巨大的背景组件，但它已被触边、面积和长边门正确拒绝。因此不能把修复简化成降低`0.24`；必须让原始肤色支撑、局部色差和既有形状门共同成立，避免把背景物体一并放入。

## 4. 候选方案与取舍

### 4.1 方案A：继续放宽灰度、皮肤邻接或面积阈值

结论：拒绝。它可能让当前某一张图多返回候选，但全图背景仍参与同一连通域，阈值越松，衣物、桌面和阴影误检越多，不能满足0背景候选。

### 4.2 方案B：只取消MediaPipe掌面整手拒绝

结论：拒绝单独采用。关键点给出的椭圆只是远端指骨几何，在掌面或弯曲手势下可能落到指腹；没有局部像素证据时直接展示会重现“衣物/皮肤被当甲面”的旧问题。

### 4.3 方案C：直接把`0.24`降到能通过当前图

结论：拒绝。机器证据证明该阈值是当前漏检点，但单独降低会让“纹理不平滑但颜色像皮肤”的背景邻域获得同等资格，无法证明0误检。

### 4.4 方案D：手部支持域 + 复合肤色/色差证据 + 候选弧排序（批准实施）

结论：批准。该方案直接覆盖当前两个漏甲的唯一拒绝原因，同时保留并增强背景隔离。核心原则是：候选必须先具有甲面形状，再由原始肤色环证明其处在手指邻域，并由候选与肤色环的亮度/色度差证明其不是普通皮肤；平滑度不再拥有单点否决权。

## 5. 拟实施算法

### 5.1 实施边界与阶段开关

1. 保持正式模型与MediaPipe现有安全降级语义；本次不部署缺失ONNX、不使用candidate5，也不把未经像素验证的掌面几何椭圆直接当甲面。
2. 第一阶段只修改有直接组件证据的局部近景检测和无关键点排序。现场图达到5/5且安全回归通过后即停止扩大改动面。
3. 只有第一阶段完成后现场图仍不足5/5，才进入第二阶段：让MediaPipe掌面结果仅生成逐指搜索ROI，再复用同一局部复合验证；ROI本身永远不直接成为甲面。
4. 该阶段开关避免在已知根因修复成功时同时改变两套召回机制，便于把回归结果归因到具体修改。

### 5.2 无关键点局部路径

1. 分析最长边从480提高到640，保留小指和高光边缘细节；浏览器仍只处理缩放副本。
2. 保留原始肤色掩码，并从最大连贯肤色组件构造小范围膨胀的手部支持域；甲面作为肤色组件中的孔或邻接区域仍可进入，但远离手部的桌面、衣物和背景不得进入。
3. 候选种子继续兼容黑色、银色和镜面高光；在连通域前增加小核开运算断开细桥，再闭运算补齐甲内高光裂缝。
4. 对每个组件同时计算`rawSkinRingRatio`、`smoothSkinRingRatio`、候选均值颜色、邻接肤色环均值颜色及二者的亮度/色度距离。
5. 硬门要求：既有面积、旋转长宽、填充率、方差、触边门全部通过；候选位于同一手部支持域；原始肤色环充分；并且候选与肤色环存在可量化局部色差。`smoothSkinRingRatio`只参与置信度和同分排序，不再单独否决。
6. 阈值先由“当前五甲全部通过、现场背景大组件仍拒绝、既有衣物/远端/单歧义物体仍拒绝”三组约束共同确定，禁止只拟合当前五个中心。每个拒绝原因写入纯函数诊断统计。
7. 同一手部支持域内保留2—5个互不高度重叠候选；优先完整候选簇和复合分数。只有4—5个候选才显示“已定位”，2—3个继续提示补充。

### 5.3 候选合并与手指分配

- 几何验证候选优先于无关键点局部候选；两条路径重叠时按中心距离与旋转框重叠去重，不重复计数。
- 有MediaPipe手指身份时保留0—4身份；无关键点时以最大肤色组件中心为掌心近似，将候选按极角排列成单调弧。候选弧两端中，较宽且相对其余四指簇更外侧的一端判为拇指，再依弧序分配食指至小指；若端点宽度、最大角间隔和弧连续性不能形成一致结论，则身份保持未分配并提示人工确认，禁止用横坐标强行错配。
- 任何两候选高度重叠、候选超出手部支持区或数量超过5时保持HOLD并进入人工复核，不自动截掉错误后宣称成功。

## 11. 第二现场图：低对比裸色/半透明甲面失效

### 11.1 新问题与证据边界

用户更换为五枚裸色/半透明短甲、含蝴蝶结线稿和圆点装饰的近景图后，页面再次返回0区域。用户本轮只提供包含界面的2549×1403截图；临时回归裁片为1201×1195、SHA-256 `b338357bb7c87a8e8b69aaf33753482b5f5b830ca13ecca4a6a33bef9deb1830`，顶部含界面提示条。裁片只用于功能复现与算法诊断，不入Git、不训练、不作为正式模型或发布质量证据。

真实页面上传该裁片后稳定复现：`backend=fallback`、总耗时约4.9秒、MediaPipe返回`mediapipe_no_hand_detected`、局部路径区域0/已分配0，控制台0 error。失败不是上传、Worker崩溃或界面状态问题。

按当前640像素分析口径逐像素复算：

- 裸色甲面与皮肤颜色接近，四枚无遮挡可见甲面的肤色分类占比分别约97.7%、100%、96.5%和100%；蝴蝶结甲及小指甲的`!isSkin && gray < 225`候选比例为0；
- 全图经开闭运算后有43个非肤色组件，但38个面积过小、34个短轴过小；唯一通过全部现有门的组件位于指缝暗阴影，不是真实甲面；因合格数只有1，安全门将整批隐藏并返回0；
- 因此本图与v1.0根因不同：甲面在候选种子阶段已经被肤色掩码吞掉，后置降低局部色差、肤色环或面积阈值无法找回真实甲面；
- 采用5×5平滑、Sobel边缘、5×5闭运算后，对边缘补集做边界连通标记，可在截图裁片上形成五个与真实甲板位置对应的闭合内部区域。两档相邻边缘阈值合并后，五中心约为`(370,104)`、`(308,183)`、`(296,303)`、`(238,401)`、`(215,464)`（640像素分析坐标）；它们均具有高肤色内部/邻环、较平滑内部和明显边界梯度，并以不超过最长边21%的间距组成单一连续链。

### 11.2 被拒绝的修法

1. **直接放宽`isSkin`或把肤色像素并入原有`painted`掩码：拒绝。** 这会把手掌、手指和同色背景合并成巨大组件，无法保持0皮肤候选。
2. **只降低局部色差18或面积门：拒绝。** 真实甲面没有进入组件阶段，调整后置门无效；只会放行现有指缝阴影或背景碎片。
3. **把MediaPipe远端指骨椭圆直接显示：拒绝。** 本图MediaPipe没有输出完整手关键点；即使其他掌面图有关键点，未经像素边界验证仍可能把指腹当甲面。
4. **全图展示所有闭合边缘区域：拒绝。** 衣物褶皱、手掌纹和背景轮廓也可能闭合，必须有甲板内部、肤色邻环、边界强度、数量和同手链式一致性复合门。

### 11.3 批准方案：颜色路径失败后的低对比甲板边界路径

该路径只在正式模型fallback、MediaPipe无候选且既有颜色路径不足2个候选时执行，不改变已通过的黑色/银色/彩色路径，也不改变正式模型契约。

1. 在已有640像素灰度副本上执行固定5×5可复现平滑和Sobel梯度；用相邻两档保守边缘阈值闭合甲缘小缺口。不得引入网络、外部模型或原图上传。
2. 对闭合边缘的补集做8邻域连通标记；任何接触图像边界的区域立即拒绝。区域继续通过面积、短/长轴、长宽比和填充率门。
3. 低对比甲板允许内部仍被识别为肤色，但必须同时满足：内部肤色占比高、外环肤色占比高、内部灰度不属于暗阴影、内部足够平滑、边界梯度充分。该组合用于区分裸色甲板、指缝阴影和普通皮肤纹理，禁止用单一阈值决定。
4. 两档阈值得到的高度重叠区域按中心距离和面积合并，保留覆盖更完整者；每个候选输出中心、主轴、长宽及`partial_closeup_low_contrast_boundary`诊断标记，仍为低置信辅助椭圆而非像素级mask。
5. 只接受4—5个候选组成的单一连续链；相邻候选中心距离不得超过分析最长边21%，孤立闭合轮廓不计入。少于4、超过5、存在两个同规模竞争簇或链断裂时整条路径返回0并保留人工添加出口。
6. 低对比路径选中后仍沿用候选弧排序；身份不能稳定判定时保持未分配，不用错误身份换取“已分配5”。提取仍需用户可见检查，界面不得将辅助框描述为正式模型PASS。

### 11.5 v1.2实施前复审结论

- **能否修复本次直接根因：可以。** 新路径不依赖`!isSkin`种子，而是从甲缘闭合结构形成候选，已在同一640分析口径取得与五枚甲板一致的五区域机器证据。
- **是否只是为当前坐标写死：不是。** 候选由像素边缘、内部/邻环统计和连通链生成，代码和测试不得包含现场坐标、文件名或哈希；截图坐标只保留在本文作为实施前证据。
- **是否会放宽旧路径：不会。** 旧颜色路径优先且门槛不改；新路径仅在其失败时触发，并要求4—5枚同链，单甲物体、散乱背景和普通平滑皮肤整批拒绝。
- **是否需要解除MediaPipe掌面安全门或部署candidate5：不需要。** 两项状态均保持不变。
- **剩余风险：** 边界非常弱、严重模糊、甲缘被装饰或遮挡打断时仍可能拒绝；辅助椭圆不等于分割mask，必须保留用户检查和人工补选。该限制比把皮肤误当甲面更安全。

最终判断：v1.2方案直接覆盖“裸色甲面被肤色种子提前吞掉”的新故障，同时用复合甲板证据和4—5枚连续链约束误检风险，批准按11.4逐步实施。任何安全回归出现非零候选、现场候选落到皮肤/背景或提取不能形成逐指纹理时，必须回到本文修订，不得继续放宽门槛。
