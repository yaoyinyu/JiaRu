# 数值部署、浏览器捕获与算子诊断

本文件是根目录 [AGENTS.md](../../AGENTS.md) 的专项规则，命中其读取条件时必须在执行前完整读取；多主题任务须同时遵守所有相关文件。当前状态、样本数、预算与路径绑定以权威文档及可重放报告为准。

同时读取：[数据身份与来源](dataset-provenance.md)、[训练与评估](training-evaluation.md)、[冻结证据与重放](evidence-replay.md)。

## 存储域、精度与完整模型门

- 跨Python/浏览器的像素逆映射必须统一概率存储精度、重采样和阈值执行顺序；Python以float32概率阈值化时，浏览器须在对应阶段显式舍入为float32。不能以浮点误差为由放宽已冻结的零像素差门或改写失败。

- 重放历史真值往返时必须保留原存储域及阈值口径（例如uint8 L/128与float32 F/0.5）；不同域应分别保存参考，不得强行要求指标相同或改写冻结参考。边界诊断的输入像素容差与原图像素容差须显式区分，不能把单位不同的指标用于因果或质量提升结论。

- 零输出初始化模型的ONNX/浏览器可行性验证必须另绑定确定性的非零未训练接口控制，避免全零输出掩盖算子或数值问题；控制不得参与模型质量选择或冒充训练权重。特征层首步梯度可能因零输出层而为零，应区分“有限且使用”与“非零”，禁止据此伪造全部层非零梯度。

- 动态原尺寸模型的浏览器数值门须从实际WASM/WebGPU原始float32捕获重放；解码mask暂时无像素差不能覆盖超限数值误差。导出表达修复应保留旧失败，明确不变的窗口、运算顺序、epsilon及学习仿射，并复验实际输入与非零未训练控制，不得只挑较小尺寸或弱化控制使门通过。

- 多输出数值核验须先逐张量检查参考端与运行端的形状及全部数值有限，再计算最大误差；小输出头的NaN可能被Python的`max(正常值, NaN)`忽略，不能只检查mask头或依赖误差比较拒绝非有限输出。

- 学得权重的推理精度政策须显式冻结（含CUDA matmul/cuDNN TF32），与权重、全候选身份及原像素输出共同绑定。精度政策变化导致logits或解码像素变化时，须另版复算完整质量门与逐实例迁移，保留旧参考/失败；禁止以新参考替换旧存档追认部署通过。诊断报告的重建ok与实际数值/容量门必须分别读取，关闭图优化或零像素差不覆盖数值超门。

## 图变更、控制与预算准入

- 新增主机元数据输入或修改数值图后，不得沿用旧图的完整模型通过结果或非零控制。完整候选须先通过同全清单、全部部署后端的确定性非零控制，才消费学得模型输入；隔离算子通过不能替代完整两头的数值、解码像素及presence门。新图、参考、开始事件和阶段预算分别冻结，控制失败时未消费的学得预算仍须保持未消费。

- 数值图修改目标必须从每份实际冻结图的语义节点和输入输出清单分别解析并绑定；确定性控制与学得图的临时节点编号可能不同，不得复用小型fixture或另一图的编号猜测目标。预检失败保留源和图绑定，另立修复版本；正式预算消费前须证明目标唯一、顺序正确及回剥恢复原图字节。

- 主机张量经Identity等语义直通节点接入设备算子时，图可逆、输入SHA相同和CPU通过均不证明设备实际消费一致；出现跨后端差异须用独立非零输入对照中转与直连路径。改变连接方式后须保留旧失败、逐消费者绑定和严格逆变换证据，并重新通过完整非零控制后才消费学得预算。

- 原尺寸域扩展的零推理可达性检查须覆盖整条部署链的尺寸守卫与内存调度，不能只检查坐标生成器；消费完整模型预算前，须逐项核验全清单实际尺寸、最大尺寸独立非零控制、活跃张量区间及固定内存上限。后续发现另一模块仍拒绝该域时，冻结原执行、已消费/未确认分母及源版本；修复另立版本和控制合同，不重启旧预算。

## 执行环境与观测有效性

- CPU数值参考与保真探针须冻结并复验设备选择后实际生效的线程数及算子后端；安装库的设备选择可能重设线程，不能把调用前的set_num_threads当作最终状态。探针必须先逐字节重建原最终输出，失败则保留reconstruction_mismatch和预算、拒绝归因；依据新环境证据另版修复，不改原参考或追认旧探针通过。

- 神经网络导出或追踪的预算钩子只能写已冻结的可序列化主机元数据，不能直接把Tensor/SymInt尺寸交给JSON，也不能为日志取值向追踪图加入运算。钩子失败须保留开始尝试、未确认前向与原异常，修复另版仅续接未消费范围，不得把失败尝试清零或据此静默重启预算。

- 运行时可选配置须先核对实际加载的分发包及生效执行分支；类型声明或另一构建分支支持，不证明当前运行时消费该字段。节点名单请求、API返回和进程退出不能代替实际落点或干预生效证据；字段未实现时保留无效配置与已消费预算，不据此否定目标算法或重启旧控制。

- GPU计算程序数不得直接作为队列提交总数：原有读回或复制等路径也可能触发提交。预注册须分开定义计算事件、提交原因与计数重放；总计数失配时保留原合同、失败和已消费预算，后续零推理RAW诊断不得追认原控制资格。

## 捕获、续接与计时

- 浏览器核验须在每个输入执行前独占持久化开始事件，并把实际两头RAW、原尺寸、稳定候选身份及冻结模型/运行资产绑定；事件与捕获顺序、基数必须独立重放，空报告或外层PASS不能覆盖缺输入。回环页超时不证明推理已消费或服务已终止，先查活动句柄、监听状态和预算事件，再处置服务；不因观察超时重启已消费推理。

- 数值张量捕获应答丢失不证明文件未保存。恢复前须按固定路径查询已落盘SHA-256和实际字节数；一致则继承，缺失才有界补传，不重跑模型、不覆盖旧文件。浏览器须消费每个应答体，HTTP尝试、唯一文件、模型开始事件分别计数；合成传输正控不能追认模型门通过或原网络根因。

- 浏览器数值捕获续接须冻结已消费与未消费的精确后端/候选身份，并以独占页面认领和每输入唯一请求ID防止刷新或不同请求冒充上传重试。仅同请求ID、SHA与字节一致可继承应答；部分层缺失须按层与后端分别保留分母，最终头保真不能补齐缺层或覆盖旧数值失败。

- 改变诊断输出集合后，捕获张量分母须从冻结模型实际输出名与完整输入清单推导，不得复用旧变体的硬编码数。预检发现计数冲突时保留工具缺陷和已消费输入，另立只读重放合同；不得为修复审核器重跑模型、覆盖旧产物或缩减分母。诊断副本节点只可用于观测且不得回馈原计算，须绑定原图剥离同构、小型非零控制及实际全候选最终输出保真，不能以副本语义自动批准观测值。

- 无头浏览器启用`--virtual-time-budget`时，`performance.now()`区间不能作为同步模型计算的真实墙钟耗时；数值捕获与成本资格须分别裁决。正式或基线成本测量必须关闭虚拟时钟，绑定浏览器单调时钟和主机进程墙钟，区分候选间隔、完整图端到端、进程生命周期与P95；发现时钟域缺失须保留原记录，另版修正，禁止把虚拟时间追认为性能通过。

## 逐层保真与数学反事实

- 逐层数值诊断须先证明只新增图输出、最终两头相对同后端未插桩存档逐字节一致，并持久化完整候选的层名、形状、float32与有限值；任一保真失败拒绝层级结论。首个跨门层不自动等于根因，须用冻结同输入隔离算子并区分上游累积误差与算子自身误差；算子诊断不能替代完整模型部署门。

- 同输入隔离算子通过只能约束算子自身误差，不能排除上游累积与后续放大，也不能替代完整模型门。解析统计/高精度数学参考须独立标明精度域、原输入和用途，不得替换冻结CUDA输出或缩小原失败分母；仅能影响一个后端的修复须先证明对全部失败可达，不能消费完整模型预算后才发现另一后端原样失败。

- 仅新增图输出且回剥后图结构逐字节一致，不证明运行数值保真；标量或形状相关中间输出也可能改变执行结果。全范围保真门失败时须保留原分母与失败，另建只读盘点，不得挑未变化后端或算子追认原追踪结论；改进可观测性先用独立非零合成控制核验，合成控制不能代替学得全候选或原CUDA参考。

- 已捕获比例能够逐字节复算坐标链，只证明该算子运算链的误差传播，不证明完整模型根因或修复充分性。求和与除法误差须分别按自身输入/分母复算；数学高精度参考不替换CUDA存档。把标量计算移至主机时，主机/浏览器的float32字节、原尺寸来源与所有新输入必须先过全清单合同，不能靠共享公式文字或只检少量控制批准候选。

- 解析误差分解须在同一原坐标比较有符号项，独立全局最大值不可直接相加或用于根因占比；理想单层数学输出未过该层诊断门，不自动证明最终两头或整个模型不可达。ONNX算子可选输入须按实际节点冻结，缺省bias不视为坏模型，也不得伪造为新增学习参数；存储/读取假设失败须保留并另版修复。

- 数学反事实跨层传递时，原模型float32常量须按实际位值提升精度，不能以数学等价常量替换；继承解析结果与新数学阶段须分别按全候选/全分支推导分母。必须先复验原输出链字节保真，最终比较继续沿冻结存储域、舍入边界、原参考与完整解码口径；反事实诊断不能冒充实际部署图通过或全模型不可达证明。

- 双头数值门失败时，须先从完整冻结RAW逐头分解误差，区分mask与presence及其独立计算路径；不能因总最大差失败就默认继续修边界头。用同一中间特征的高精度归约或线性重建只能作为明确标识的反事实诊断，不能冒充实际模型输出；修复必须保持原权重/参考/门限并通过完整独立控制及学得图验收。
