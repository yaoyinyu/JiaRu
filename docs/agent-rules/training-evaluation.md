# 训练、评估与预算

本文件是根目录 [AGENTS.md](../../AGENTS.md) 的专项规则，命中其读取条件时必须在执行前完整读取；多主题任务须同时遵守所有相关文件。当前状态、样本数、预算与路径绑定以权威文档及可重放报告为准。

同时读取：[数据身份与来源](dataset-provenance.md)、[冻结证据与重放](evidence-replay.md)；发送图片时补读[整图视觉审核](visual-review.md)。

## 训练输入、执行与进度

- 任何对哈希绑定数据集执行只读分析、吞吐基准或扫描的临时脚本，必须先安装与项目训练器等价的只读图片守卫（阻止 Ultralytics `check_image` 把缺少 EOI 字节的历史 JPEG 以 quality=100 原地重存），并串行绑定"结束后删除 Ultralytics 生成的 `labels/*.cache`"。只有通过该数据集物化报告的权威重放（如 `materialize-development-cycle-012-dataset.py --verify-report`）确认文件清单与 `datasetFilesSha256` 一致，才可声明数据未被改动；擅自以 PIL/Ultralytics 直读证据数据集而不装守卫即视为破坏可重放证据。优先在隔离副本上跑基准，不要在证据目录内运行。

- 用 Ultralytics 手工基准测量训练步时必须显式 `requires_grad_(True)`：`YOLO(...).model` 以推理默认加载、所有参数 `requires_grad=False`，`.train()` 只切模式不改梯度开关，否则得到的损失无 `grad_fn`；且本版本 `model.loss(batch)` 返回 `(box, seg, cls, dfl, sem)` 分量向量，反向需先 `.sum()` 标量化。补充：`on_val_end` 回调传入的是 Validator（无 `.epoch`），需要每 epoch 计时请改用 `on_fit_epoch_end`（传入 Trainer）。

- 长训练必须原子持久化成功优化步、epoch及执行状态，并在异常时生成终止报告；最近一次控制台输出只能证明已确认的进度下界，不能当作精确终止步数。缺少完整checkpoint时不得声称可断点续训；已消费实验预算不能静默重启。

- Windows长训练进度应使用不可覆盖的唯一事件文件与flush/fsync，终态快照只创建一次；共享读取锁可能阻止os.replace，不能只用无并发的顺序写入测试证明可靠。异常报告应独立创建，避免先覆盖共享进度文件而再次失败、丢失原始异常；取证checkpoint不自动构成已消费预算的续训权限。

- 动态加载训练器安装只读图片守卫前，须确保其同目录辅助模块在模块搜索路径中；加载或安装失败时禁止进入像素解码，保留失败并修复加载路径后另版运行，不得忽略异常或移除守卫。

- 训练器的`on_fit_epoch_end`也可能在最终best验证时触发，且安装版本会临时将`Trainer.epoch`加一；不得把每次回调的`epoch+1`直接累计为训练轮数。须按实际训练epoch、成功优化步及CSV核对，最终验证单独留证且不新增训练epoch/checkpoint。发现收尾计数异常时保留原终态和预算，只能另版只读核验实际执行，禁止借此重训或把质量失败改为通过。

- 多输出模型改变训练目标的分支使用范围时，须预注册逐目标应使用与应不使用的参数分支；未使用decoder的`grad=None`不能冒充全部参数梯度通过，也不能按旧全分支断言误报。最终拒识/空输出门、候选身份、正例目标和数据角色须继续保持。

- 训练计划声明的数据增强必须与实际训练调用路径及执行计数一致；仅配置存在或预检梯度通过不能证明增强已执行。发现失配保留原预算、权重及失败，以新合同明确修复或禁用，不追认原实验通过。模型前向后须先独占持久化原始两头输出，再执行指标和后处理，避免读取器错误造成已消费输入无RAW可重放。

## 调整计数、缓存与执行环境

- 模型成果按用户要求每累计完成10次实际模型调整集中展示一次，不限于微调。一次指已实际执行、保留独立模型版本或训练预算并完成相应验收的模型变更；结构、损失、训练策略和实际推理图修复均可计入，验收失败也须如实保留。同一调整跨训练、导出与验证不重复计数，epoch、优化步、纯测试、审核、重放或文档记录均不计数。按真实产物与终态报告绑定持久化计数，未满周期不主动打开成果预览；必要质量验收仍执行，不为凑数修改模型、跳过验收或重启已消费预算。

- 训练输入缓存须与当前安装训练器的实际`load_image`输出逐图逐字节比较，同时保留原尺寸、缩放尺寸及增强buffer状态语义；仅公式相同不足以证明等价。训练输入尺寸缓存不能替代完整原像素审核。CPU/GPU执行设备切换须另立设备和预算合同，CPU完成不得追认GPU失败为通过。

- 训练线程和执行后端必须在设备选择完成后记录实际生效值；安装库可能重设线程，调用前设置仅代表意图。CPU专用依赖、导入或首批通过不能证明完整训练资源可执行；原生退出无内层终态时由独立监督冻结进度下界和部分checkpoint，部分权重不得冒充完整合同或自动续训。

## 质量、阈值、可达性与对照

- 验证集真值必须逐图通过原分辨率完整甲面审核；任一图片仍为返修或排除、存在未声明交叠、漏甲、重复、误标或污染时，整套 split 不得用于模型选择或阈值校准，基于该真值产生的高指标只能保留为历史诊断。

- 模型`scoreThreshold`只能使用来源隔离且未进入train/test的`val`证据校准；冻结test、发布测试及其派生物禁止参与阈值选择。验证集少于30张、存在需修复真值polygon或未通过召回/误检/候选数门时，只能输出诊断阈值，禁止写入候选或生产manifest。

- 模型发布质量必须以实际部署输入尺寸和来源隔离的冻结测试快照判定；更高输入尺寸的诊断结果或历史小测试集不得覆盖扩展快照在部署口径上的失败。失败快照必须继续禁止训练，改进候选只能使用获得训练授权且与冻结测试来源隔离的新样本。

- 冻结测试集上的置信度扫描只能用于候选诊断；降低阈值提高召回时，必须同时审核误检、浏览器候选数量上限和Beta直接可用率，禁止仅凭离线召回提升修改共享默认阈值。

- 来源标记干预的空白窗口须与标记窗口背景类别匹配并原像素复审；甲面零像素变化不证明背景语义匹配。移位复制背景patch时须补齐同目的窗、尺寸、底图及合成方式的空白移位控制，未闭合前只能作诊断，不能据此归因模型捷径。

- AI生成困难负样本不得因来源为AI而放宽清晰度、完整性、真人甲面排除或原分辨率审核门；若负样本存在系统性水印、模糊角标或生成器特征，正式晋升前必须完成原图与去水印/遮挡变体的误检消融，禁止让模型以来源标记代替真实视觉语义。

## 候选分配、可达性与诊断分母

- 固定IoU门未匹配不等于没有候选，未匹配预测也不自动等于背景误检；必须保留逐甲候选分配并区分mask质量、候选数量和有效ROI覆盖。Stage A缺失须用冻结ROI覆盖口径另证，禁止以未匹配真值数替代；候选数等于真值数也不能证明完整mask或零误检。

- 消耗唯一训练或推理预算前，必须先做零推理**可达性判决**：用已冻结证据判断目标失败是否在假设最优后仍不可达（本例逐甲mask替换受限于“该漏甲处根本无候选”），并给出理论上限与可达余量的比值；天花板不达标即按`unreachable`结项并停止，不得用“先训一版看看”代替可达性证明。

- 开发相对门（如漏甲图数从13降到10）在小样本上可能不可判别：任何相对门结论都必须同时给出Wilson 95%区间与同分母最小可判别差，并列出让该门可判别所需的最小样本量；相对门落在基线区间内时，只能作为方向性提示，禁止单独作为分支保留/关闭依据。

- 条件分割的空目标只否定当前候选，不能据此把包含邻甲的整块RGB ROI标为“没有甲面”；必须绑定同一候选粗mask及稳定候选身份，保留全图真值分母。明确拒识应剔除该候选，不能回退粗mask后计为自动成功；执行错误与有效空输出须区分。

- ROI覆盖上限必须以同候选粗mask种子和一一候选分配计算，禁止一大框重复覆盖多枚甲面而累计成功；未裁减候选的诊断上限与部署候选预算下的上限须分开验证。完整甲面落在ROI内仅证明几何容纳，不证明目标提示唯一、精细分割、来源资格或正式可用率。

- 前移重复抑制或改变候选截取顺序时，须另立版本保留原接受集合、原一一分配及原失败；按新集合显式绑定目标迁移与粗mask质量代价。几何覆盖恢复不等于mask质量提高，被抑制或截断项须原像素复核为冗余且无独立甲面丢失，禁止自动标背景或空训练目标。

- 配对诊断包含仅原图成员或各源变体数不同时，必须从稳定来源身份及逐输入清单推导并冻结全原图、配对原图和每个变体的来源数/真值数，禁止硬编码统一分母；消费预算前须取得机器分母合同审核`ok=true`，进程退出0或失败报告重放一致均不等于合同通过。预注册说明与逐源清单冲突时输出`reconstruction_mismatch`并拒绝资格结论，保留原计划、失败及已消费预算；后续只读分析须另立正确合同，不得覆盖旧版、静默重启推理或追认原失败为通过。
