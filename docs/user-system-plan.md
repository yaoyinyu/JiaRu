## 1. 背景与目标

甲如当前是纯浏览器本地应用：无账号、无后端数据库、无云存储，所有功能（试色/AI 生图/AR）不登录即可使用（白皮书 §3 状态表：用户账户、云同步、商城/门店为「未完成」）。

正式上线后需要用户管理系统，目标：

1. **三类角色 + 游客**：个人用户、商户（美甲店）、平台管理员（超管）、游客（不登录）。
2. **云端资源管理**：登录后解锁云端作品、收藏、历史、AI 配额与存储配额。
3. **商户体系**：入驻审核、门店款式库、子账号、客户线索（商业模式核心）。
4. **合规基线**：符合《个人信息保护法》的同意、删除、导出、注销要求；衔接既有「用户改进计划」开关（v1.1.470）。
5. **不破坏现有功能**：游客体验保持现状，现有页面接口契约不变。

## 2. 草案审查结论与逻辑链修正（必读）

对两轮草案（v1.1.468/v1.1.469）逐条推演后，修正如下。**开发实现必须以本节为准，不直接引用原始草案。**

### 2.1 重大修正 M1：改进计划开关是手图收集的唯一闸门

- 原草案矛盾：「源图永不上云」与「改进计划默认开启（可能收集手部照片）」冲突。
- 修正后的完整逻辑链：
  1. 手部源图（可能含指纹，属生物识别敏感个人信息）**默认仅在浏览器本地处理，不进入任何云端资源**；
  2. **唯一例外**：「用户改进计划」开关（`jiaru-improvement-program`，现有 localStorage 实现）处于开启状态时，手部照片/AR 画面可上传用于产品改进（模型训练）；
  3. 开关关闭 → 任何功能均不得上传任何图片数据；
  4. 开关状态以**账号级偏好**为准（有账号时存服务端，跨设备一致；游客以设备 localStorage 为准，见 §5.6）；
  5. 改进计划收集的数据**去标识化**后存入独立的"改进计划样本库"，与业务数据库物理隔离，且必须走项目既有训练授权链（见 §9.5）。
- ⚠️ 合规红线：生物识别信息按《个保法》要求"单独同意"，"默认开启"的 opt-out 模式是否构成有效单独同意，**上线前必须由法律复核**；若复核不通过，改为"首次使用相关功能时弹窗明示同意"（默认不勾选）。本文档保留用户要求的"默认开启"为现状，但不替代法律结论。

### 2.2 重大修正 M2：游客 → 注册的数据迁移

- 原草案缺口：游客在本机产生的数据（收藏、历史、自定义色板、作品）注册后如何合并未定义。
- 修正：注册/登录成功后，执行「本机数据合并」流程（§5.4）：检测浏览器本地存储中未归属账号的资源 → 提示用户"发现 N 项本机数据，是否合并到账号" → 用户确认后上传合并（按内容哈希去重，账号数据优先，冲突时保留两份并标记）。用户拒绝合并则本机数据保留在原设备，不删除。

### 2.3 重大修正 M3：部署必须区分"全球版"与"国内正式版"

- 原草案缺口：技术底座写 Vercel（海外），但收集手机号+手部照片（生物识别）在国内正式运营要求**数据境内存储 + ICP 备案**。
- 修正：
  - **全球/演示版**（不收集个人数据、无账号）：可继续 Vercel 部署；
  - **国内正式版**（含账号、改进计划收集）：需境内服务器（阿里云/腾讯云等）+ ICP 备案 + 境内对象存储 + 国内短信服务商 + 国内内容安全审核服务；
  - 数据不出境：账号、作品、改进计划样本、日志全部境内存储；第三方服务（Agnes AI 生图）仅接收文字描述，符合现状。
- 该决策（部署地域）是**开工前的硬前提**，列入 §12 决策点。

## 3. 角色与权限模型（RBAC）

### 3.1 角色定义

| 角色 | 如何获得 | 说明 |
| --- | --- | --- |
| 游客 | 默认 | 不登录，全部现有功能可用，无云端资源 |
| 个人用户 | 任一登录方式（手机号/微信，登录即注册） | 云端作品、收藏、历史、配额 |
| 商户·店长 | 个人账号申请入驻 → 超管审核通过 | 门店款式库、子账号管理、客户线索、数据报表 |
| 商户·店员 | 店长创建子账号 | 协助管理款式库（权限受限） |
| 平台管理员（超管） | 系统配置（不可自助注册） | 入驻审核、用户管理、内容审核、封禁申诉、看板 |

| 云端作品/收藏/历史 | ✗ | ✓ | ✓ | ✓ | 审计 |

### 3.3 身份升级与账号合并

- **个人 → 商户**：同一账号申请入驻（叠加商户身份），审核通过后启用商户能力；**不重新注册**，原有收藏/历史/作品全部保留。
- **账号合并**：手机号注册与微信登录可能产生两个账号。登录时按手机号/微信 OpenID 匹配已存在账号自动绑定；无法自动匹配时提供"绑定到已有账号"入口，合并前需双方验证（短信验证码 + 微信授权）。

## 5. 核心流程

### 5.1 注册与登录

**设计原则：登录即注册（一体化）。** 无独立注册表单；用户选择任一登录方式时，系统按该方式的身份标识查 `user_identities` 绑定表：已存在 → 登录；不存在 → 自动创建账号并绑定该方式（首次登录即注册，用户无感）。

**支持的登录/注册方式（2026-08-15 起按用户要求：先做手机号 + 微信，邮箱/GitHub 已砍掉）：**

| 方式 | 适用场景 | 实现 | 注意点 |
| --- | --- | --- | --- |
| 手机号 + 短信验证码 | 国内主力 | 阿里云/腾讯云短信 | 验证码 5 分钟有效、同号码 60 秒节流、单日上限 10 条（防轰炸）；**发送验证码前必须先通过人机验证（图形验证码）**；免密登录 |
| 微信扫码/授权登录 | 国内用户习惯 | 微信开放平台"网站应用"OAuth 2.0 | 需认证企业主体（300 元/年）；微信仅返回 openid 不提供手机号，**首次登录必须补绑手机号**（合规） |

> 变更记录：邮箱+密码、GitHub OAuth 登录入口已按用户要求移除（2026-08-15，白皮书 v1.1.477）。若未来需要恢复，Git 历史中有完整实现。

**主身份与绑定关系：** 手机号为主身份（注销、找回、安全提醒通道）；微信为绑定方式，同一账号可绑定多个（`user_identities` 表），任意一种均可登录，数据共享同一账号。

**首次登录流程：** 验证成功 → 查绑定 → 无则创建账号并绑定 → **微信首次登录必须补绑手机号**（合规要求：实名可追溯）→ 触发游客本机数据合并（§5.4）→ 返回 JWT。

- 可选设置密码（用于换手机号等场景）；密码哈希 bcrypt/argon2，复杂度 ≥8 位；**邮箱注册新账号必须创建密码并二次确认（两次输入一致，服务端校验）**。
- 登录成功后返回 JWT（短时 2h）+ 刷新令牌（30 天）；会话存服务端 session 表，支持按设备列出/踢下线。
- **人机验证**：发送短信验证码前必须通过图形验证码（4 位字符 SVG、5 分钟有效、一次性、错 5 次作废；答案仅存服务端）；后续可升级为专业人机验证服务（腾讯云/阿里云验证码），接口不变。

### 5.2 设备管理与异地登录提醒

- 每次新设备/新地点登录：记录设备指纹+IP+时间，向用户短信提醒"新设备登录"。
- 用户可在"账号安全"页查看全部会话并踢下线（被踢会话立即失效）。
- 连续失败登录：同账号 5 次失败锁定 15 分钟；跨 IP 撞库尝试风控告警。
- **登录方式管理**：账号安全页展示当前已绑定的全部登录方式（手机号/微信），支持解绑（至少保留一种可用方式）、新增绑定（需验证新方式 + 当前登录态）。

### 5.3 账号申诉找回与换绑

- **自助换绑手机号**：旧手机号仍可收码 → 验证旧号（短信）→ 验证新号（短信）→ 换绑成功，旧号从 `user_identities` 解绑；全程审计留痕。
- **邮箱密码找回**：提交邮箱 → 发送重置链接/验证码（15 分钟有效）→ 重设密码 → 强制该账号其他会话下线。
- **手机号不可用时的申诉**：提交申诉（历史登录设备、曾用昵称、作品信息等佐证）→ 超管人工审核 → 通过后换绑新手机号。
- 申诉全程审计留痕。

### 5.4 游客 → 注册数据迁移（M2）

```
游客在浏览器本地使用（localStorage/IndexedDB：收藏、历史、色板、未上传作品）
        ↓ 注册/登录成功
检测本机未归属账号的资源 → 弹窗："发现 N 项本机数据，是否合并到账号？"
        ↓ 同意                          ↓ 拒绝
上传合并（内容哈希去重；          本机数据保留在原设备，
账号已有同内容则跳过）            账号从空开始
```

### 5.5 注销、导出与删除（个保法）

- **注销**：两步确认 → 账号立即禁用（不可登录）→ **30 天后悔期**（期间可登录恢复，恢复即取消注销）→ 期满永久删除全部个人数据（作品/收藏/历史/会话）；同时**撤回改进计划同意**（M8）：已收集样本按用户选择删除或彻底匿名化。
- **数据导出**（可携带权）：用户申请 → 打包 ZIP（作品/收藏/历史/账号档案）→ 7 个工作日内提供下载链接；导出记录审计留痕。
- **删除**：所有删除先进回收站（30 天），可恢复；期满物理删除。

### 5.6 改进计划偏好同步（M1 细化）

- 未登录：以设备 localStorage 为准（现有 `ImprovementProgramToggle` 组件，key `jiaru-improvement-program`）。
- 登录后：偏好以**账号为准**（服务端存储）；登录时若账号无记录，将设备偏好上传为账号初始值；账号值变更同步写回当前设备 localStorage。
- 任何上传动作执行前**实时读取**当前生效偏好；关闭状态下网络层断言：无任何图片上传请求。

### 5.7 商户入驻审核

```
个人账号申请 → 提交：营业执照、门店照片、联系人 → 状态 pending_review
→ 超管审核：通过 approved（发认证标识）| 退回补充材料 | 拒绝 rejected（可再次申请）
→ 通过后账号叠加商户身份，解锁款式库/子账号/线索/报表
→ 后续：定期复核；违规可 suspend（冻结商户能力，不影响个人功能）
```

### 5.8 客户线索（m1 落点）

**线索是什么：** 用户对某商户款式的行为（浏览/试戴/收藏）以脱敏记录的形式沉淀到商户端，帮助门店识别高意向客户（商业模式核心）。

**知情同意与脱敏（合规关键）：**
1. 用户进入任一商户款式场景前，页面明确提示："你的浏览/试戴行为可能被该门店看到（仅显示匿名标识，不显示你的手机号/昵称）"；
2. 用户在"隐私与安全"页可**全局关闭**线索收集（关闭后不再产生任何线索，已有线索保留但不展示新行为）；
3. 线索仅含：匿名访问者 ID（不可反查用户身份）、行为类型（浏览/试戴/收藏）、款式、时间；**绝不向商户展示**手机号、昵称、头像、地理位置；
4. 用户注销账号时，其全部线索一并删除。

**商户端视图：** 商户后台"客户线索"列表（脱敏）+ 每款式的浏览/试戴/收藏统计（§3.2 权限：店员受限、店长全量、超管审计）。

- 扣减时机：请求受理时预扣；**服务端 5xx 失败回退次数**；用户取消不扣。

## 9. 安全与合规

### 9.1 认证与传输

- 全程 HTTPS；JWT 短时+刷新令牌轮换；验证码防轰炸；登录失败锁定。
- 密钥（短信服务、存储签名、微信 AppSecret、GitHub Client Secret）仅服务端，遵守既有 `AGNES_API_KEY` 同类规则。
- OAuth 登录（微信/GitHub）必须使用官方回调流程 + state 参数防 CSRF；GitHub 属境外服务，其授权跳转涉及跨境身份数据传输，全球版/国内版均需在隐私政策中明确告知（国内正式版如上线 GitHub 登录需法律复核跨境传输合规性）。
- 邮箱注册需防垃圾注册：验证码/激活链接 + 注册频控（同 IP/同设备）。

### 9.2 未成年人保护（M7）

- 注册时选年龄区间；<14 岁：默认关闭改进计划收集，涉及个人信息的处理要求监护人同意（提示监护人联系方式验证）。
- 改进计划样本收集前校验：账号未成年且无监护人同意 → 拒绝收集。

### 9.3 权限与多租户隔离（M10）

- 所有资源 API 经统一权限中间件：校验 token → 角色 → 资源归属（`user_id`/`merchant_id`）。
- 商户子账号强制本店 `merchant_id` 过滤，越权访问返回 403 并审计告警。

### 9.4 审计日志（M5）

- 必记操作：登录/登出、换绑、注销、导出、入驻审核、封禁/解封、款式删除、配额修改、超管全部操作。
- 留存：一般 ≥6 个月；交易/审核类 ≥3 年。日志只追加、不可修改，仅超管可查。

### 9.5 改进计划与训练授权链（M3/m4）

- 样本上传：仅当偏好开启；上传时剥离账号标识/EXIF/设备信息（去标识化），生成 SHA-256 与来源记录。
- 样本入库独立存储（不进业务库），初始 `trainingUse=prohibited`；进入训练前必须复用项目既有授权链（授权记录、质量门、来源隔离），未过门禁禁止训练——与白皮书 §9 训练治理完全一致。
- 样本不出售、不用于广告、不回流业务数据。

### 9.6 内容审核

- AI 生图结果、用户上传的款式图、评价文本走内容安全审核（国内版：接入合规审核服务）。
- 审核不通过：资源隐藏/拒绝发布 + 通知 + 申诉通道；举报工单人工复核。

### 9.7 备份与容灾

- 数据库每日自动备份（保留 30 天）+ 对象存储多副本；恢复演练季度一次；RPO ≤24h、RTO ≤4h（初值）。

## 13. 验收标准（Phase 1 为准）

- [ ] 注册 → 登录 → 云端保存作品 → 换设备登录，作品/收藏/历史完整同步
- [ ] 多方式登录：手机号/微信任一方式均可登录或自动注册；微信首次登录强制补绑手机号；同一账号多方式绑定后任一方式登录数据一致
- [ ] 登录方式管理：可查看/解绑/新增绑定，至少保留一种方式；解绑需当前登录态验证
- [ ] 自助换绑手机号：旧号+新号双验证成功；邮箱密码找回可重置密码并使其他会话下线
- [ ] 游客操作后注册，本机数据可一键合并，无丢失（含自定义色板）
- [ ] AI 配额：个人超额返回 429 与明确提示；游客 IP 限流生效（换设备仍受限）
- [ ] 注销：两步确认 → 30 天内可恢复 → 期满数据彻底删除且审计留痕
- [ ] 导出：ZIP 含作品/收藏/历史/色板/档案，限期内交付
- [ ] 改进计划：关闭后网络层断言无任何图片上传；开启时样本去标识化入库且 `trainingUse=prohibited`
- [ ] 客户线索：未同意场景不产生线索；关闭后不再产生；商户端仅见脱敏标识（§5.8）
- [ ] 审计日志：登录/注销/换绑/导出/配额修改/登录方式变更等操作完整可查
- [ ] 游客回归：不登录时现有全部功能与今日版本行为一致
- [ ] 全量测试与生产构建通过（沿用既有质量门）
