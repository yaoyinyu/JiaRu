## 推送完成：helper-selector 根因修正与 SSH 备用通道诊断（白皮书 v1.1.584）

- **修正前一轮的错误结论**：`cmdkey /list` 输出是 UTF-16 编码，grep 判定为二进制静默丢弃，导致"Windows凭据库无 `git:https://github.com` 条目"的误判。去空字节 + `grep -a` 后确认凭据管理器有 3 条 GitHub 条目，`git credential-manager get` 实测返回 username/password（仅统计字节数与键名，未打印值）。
- **真正的断点**：系统级 `credential.helper=helper-selector` 在无 TTY 环境无法转调 manager（`git push` 报 `could not read Username`）。次要障碍：schannel 证书吊销检查失败（`CRYPT_E_NO_REVOCATION_CHECK`；本机代理环境变量已从 2197 变为 `127.0.0.1:7098`）。
- **关键坑**：`GIT_CONFIG_SYSTEM`/`GIT_CONFIG_GLOBAL` 指向 `/tmp/...` 时 git.exe 不识别（Git Bash 虚拟路径），配置静默不生效——与既有经验"GIT_ASKPASS 必须 `C:/...` 路径"同源。
- **成功推送**：`GIT_CONFIG_SYSTEM=<空文件C:/路径> + 清空 http_proxy/https_proxy + git -c credential.helper=manager -c http.schannelCheckRevoke=false push origin master` → `c6f473b..6d52340`，两个提交上远端。历史佐证：`.git/logs/refs/remotes/origin/master` 有 21 条 `update by push`，最后一次 2026-09-03 10:00:39（Codex 在有 TTY 终端每次 commit 后 4—5 秒推送成功），凭据与网络长期可用。
