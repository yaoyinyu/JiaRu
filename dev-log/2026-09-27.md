## M2 refresh token 轮换修复、全量验证与云端同步部署

- 承接上一轮验证结论：M2 是本轮唯一「问题真实存在且修复方案已验证可行、但代码尚未接上」的遗留项。按用户要求实施修复 → 全面验证 → 同步云端 → 再次验收。**本轮为代码变更，故按 `AGENTS.md` 在 §13 新增条目 v1.1.720 并同步白皮书头部版本**（与上一轮纯验证不同）。
- **实现**：`SessionRow` / `user_sessions` 增加 `refresh_nonce`、`prev_refresh_nonce`、`prev_nonce_expires_at` 三列（沿用 PRAGMA 惰性迁移，无需手工刷库）；`JwtPayload` 增加可选 `jti`，`issueRefreshToken` 每次签发新 `jti`。`renewFromRefresh` 判定链：当前 nonce 命中 → 换新；旧 nonce 命中且在宽限期 → 并发容忍换新；均不命中 → 视为重放，撤销整条会话并写 `refresh_replay_detected` 审计日志。宽限期默认 5 分钟、由 `JIARU_REFRESH_GRACE_SEC` 覆盖（上限 24h）。
- **两个坑，值得记**：
  1. 第一版给 `issueRefreshToken` 加了 `jti` 参数并写进 payload 对象，但忘了让 `signJwt` 把它写进令牌 JSON 体 —— 结果所有 refresh 令牌都不带 `jti`，`renewFromRefresh` 一律返回 null。令牌字段改动必须端到端验证解码结果，不能只看类型通过。
  2. `requireUserWithRenewal` 共 13 处调用点，**其中 `/api/generate-ai` 与 `/api/generate-seedream` 此前只校验会话不回写 Cookie**。轮换一旦落地，这两个生图入口会在续期后把新 nonce 丢弃，用户被静默登出。已改为 `applyRenewedCookies` 包装响应。教训：改会话语义必须枚举全部调用点，逐个确认「读」与「写」成对存在。
- **测试**：`tests/auth-session-integrity.test.ts` 中 2 条编码旧「可复用」「临近过期才滑动」语义的用例已重写，新增 5 条覆盖轮换链、宽限期并发、超窗重放撤销、环境变量可调、历史无 nonce 会话放行。全量 940 例：511 通过、427 失败，427 与 `e45f158` 基线逐例同构（美甲模型线与训练数据审计域，与本次改动零引用交集），新增 3 例通过，**0 回归**。
