## Agnes API 生图失败只读诊断（用户反馈：最近生成总失败）

- 任务启动复核白皮书 v1.1.482 §4.4 与 `src/lib/agnes-image-api.ts`、`src/app/api/generate-ai/route.ts`，确认错误分类（401 Key 无效 / 429 频率过高 / 502 供应商错误 / 503 重试耗尽 / 504 超时）与参数（`DEFAULT_TIMEOUT_MS=180s`、`DEFAULT_MAX_ATTEMPTS=4`、仅 503 指数退避重试）。
- 实测一：`GET https://apihub.agnes-ai.cn/v1/models` → HTTP 200，返回 7 个模型，`agnes-image-2.1-flash` 可见 → 认证与配置有效，排除 Key 失效。
- 实测二：真实生成请求（model=agnes-image-2.1-flash、1024×1024、url 输出、简单 prompt）→ **HTTP 200 成功，但耗时 157.2s**，接近 180s 超时上限。
- 结论：Agnes 文生图上游排队耗时波动大（本次成功案例已 157s），一旦超过 180s 客户端 AbortController 中止并报「Agnes API 请求超时（180s），请重试」（504）；此外 429（短时频繁生成）、502（上游错误）、503（重试耗尽）也可能出现。另核实部署隐患：route `maxDuration=300`，Vercel Hobby 套餐函数上限仅 60s（Pro 才 300s），若已部署到 Hobby 则任何生图都会平台级失败；本地 dev 无此限制。
- 未修改任何代码或配置；建议（待用户确认后实施）：①`timeoutMs` 180s→280s（≤maxDuration 300）；②504 超时也纳入重试（当前仅 503 重试）；③前端/文案提示生图通常需要 2—3 分钟。

## 两套系统提示词互斥启用契约确认与强化（用户澄清）
